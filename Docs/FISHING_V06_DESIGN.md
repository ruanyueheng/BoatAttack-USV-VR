## 目标与非目标

用一条海陆任务让四个现有区域产生不同用途，首次体验目标 10–15 分钟，需真人试玩校准。
核心：找线索 → 回收组件 → 修复可见设施 → 获得海上目标 → 返港交付。
不做自由建造、动态搬箱、拖曳、多人物对话、多人同步、真实潮汐或新鱼种美术。
不拆原地图边界，不假定远景岛屿具有可用碰撞和岸线。

## 最小任务内容

1. 港口公告接受委托；可不接受，不阻断原捕鱼。
2. A 西湾：阅读维修记录，得知组件在南岸。
3. D 南岸：三个有不同标记的候选箱，正确箱有维修符号；候选位置必须人工和自动化验证可达。
4. C 旧港：安装组件；旋转信标对准一个明确的航道标记，主动确认后完成。
5. B 北岛附近：解锁一项使用现有鱼种的指定水域捕获目标。具体捕获位置必须验证船只能抵达；不直接把陆地航点当作渔区。
6. 港口：独立任务交付按钮完成任务。首版主要奖励为永久点亮信标和日志纪念，不额外堆金币；后续平衡再确定金币数额。

信标修复提供可见反馈：模型状态、发光材质、地图图标和日志变化。先不使用体积光。
辅助提示分为区域提示、地标提示、玩家主动开启的精确指引。不使用不可辨认的细小标记强制猜谜。

## 状态与防卡死约定

建议保存单调事实标记，而不是只保存一个线性的任务阶段：
Accepted、RecordRead、ComponentFound、BeaconRepaired、TargetCaught、Delivered。
当前目标由事实推导；每个状态转换通过统一规则方法校验。
- RecordRead 与 ComponentFound 允许在接任务前获得；接受后识别既有进度。
- BeaconRepaired 要求 Accepted、RecordRead、ComponentFound；组件获得事实保留，修复后表现为已使用，不再显示船上货箱。
- TargetCaught 要求 BeaconRepaired，且本次成功入箱事件满足明确的海域和鱼种条件；既有库存不能自动补算。
- Delivered 要求 Accepted、BeaconRepaired、TargetCaught；重复交付无效果。
- 最终交付采用“已记录捕获证据”，不消耗鱼、不预留库存；捕获后出售或放生不造成软锁。UI 必须叫“提交捕获记录”，不能叫“交付鱼货”。
- R 救援保留任务事实；任务物品不占鱼箱、不允许丢弃；无物理运输惩罚。
- 失败或取消旋转不会消耗组件；再次交互可以重试。
- 修复结果从存档重建，不只保留场景对象临时状态。

旋转交互：进入后停止步行；左右输入调整，E 确认，Esc 取消；退出、暂停、失焦、救援均释放输入占用。目标角度与容差显式配置。若未对准，提供方向性反馈。
候选箱首版采用固定正确箱和固定位置，不引入随机种子或重复刷新刷取问题。

## 已确认的接入点与缺口

- FishingModel.cs：FishingSaveData 当前 version=4；FishingCareer 包含 Snapshot、TryRestore 和海岸调查奖励。
- FishingPrototype.cs：Interact 在 Ashore 时直接调用 Shore.Survey 后返回。新交互必须先统一选择目标，不能并列监听 E 后让一次按键同时完成调查和安装。
- FishingShore.cs：Survey 只支持 NearbyTask 与八项调查记录。保留原调查，新增任务交互解析；显示的提示必须与实际被触发的目标一致。
- 港口 Interact 可能领取调查奖励后继续交订单/售鱼。新剧情交付首版走明确独立按钮，避免奖励提示被覆盖及多次交易。
- 捕鱼目标的捕获事件入口、坐标传递与保存时序尚需进一步读取确认，不在设计阶段假定已有通用事件总线。
- 北岛目前是登岸目的地，不等于已实现第四渔区；为最终目标新增一处局部捕鱼点是明确的额外工作，导航不能继续依赖固定三个普通鱼区的隐含假设。

建议新增独立纯规则文件 FishingExpedition.cs，以及场景协调组件；文件名为建议，尚未创建。
避免将任务状态、旋转输入和所有场景模型都塞入 FishingShore。

## 与旧玩法兼容

原“修复海岸信标”调查仍保留其历史 task ID、记录和奖励；显示文案可改为“登记信标故障”。不要修改 TaskMask/RewardMask 位含义。
新任务实际修复是独立事实：旧玩家即使已完成八项调查，也可完整体验新任务，不重复取得原每区 25 / 全图 60 奖励。
建议存档升级 v5；v1–v4 缺失任务数据时初始化为未开始。旧版本携带不应存在的新字段时按既有严格校验策略处理。
验证非法状态组合、未知位、版本边界和备份恢复。旧版本程序不得重写升级后的存档。
金币、现有订单、鱼箱、装备和传说鱼状态必须不受迁移影响。

## 必须覆盖的验收案例

规则：正常流程；先找组件后接任务；重复调查；重复安装；重复交付；不合格捕获；修复前捕获；鱼箱满导致入箱失败；任务完成后再捕获。
存档：每阶段保存恢复；v4 八项调查全完成迁移；旧金币/鱼箱不变；非法组合拒绝；备份恢复；最终交付不重发。
场景：所有目标步行/航行可达；原上下船正常；任务对象不挡通路；提示与 E 实际目标一致；取消旋转可移动；暂停/失焦无输入泄漏；R 救援恢复船只控制。
体验：不开精确指引也能依靠线索推进；卡住时可主动求助；远处可辨认修复成果；途中仍可捕鱼；没有强制等待天气的停滞。
VR：本版仍按桌面验收。PICO 抓取、头显碰撞、舒适移动及性能需独立方案与真机验证。
