# 玩法候选：先寻找可反复游玩的核心机制，不锁定“救援”

状态：设计提案，尚未实施。平台基础与题材分开；当前保留原版竞速作为可测试基线。

## 1. 群岛危险货运（推荐先试）

一句话：驾驶一艘小艇，把难运的货物送到不同岛屿，而不是单纯开得更快。

核心决策：短路礁石多，绕路会超时；高速会损坏易碎货物；负重和拖带改变操作手感。
每局从港口选择合同，选择航线，运输与靠泊，结算损坏、时间和报酬。

关键交互：固定货箱、操作油门、低速靠泊、交付；PC 用瞄准/选择加 E，VR 用射线或手柄抓取，但调用同一操作命令。
最小试玩：原海岛一张地图、两条路线、一个取货点、一个交付点、一件易碎货物、一次结算。
第一版货损用碰撞和加速度阈值模拟，货箱固定在甲板；不立即做自由滚动货物、复杂绳索或船体变形。
BoatAttack 可复用：水面、驾驶、碰撞体、海岛和航点；新增合同、货物状态、靠泊判定。
扩展：多订单路径规划、燃料与维修、天气预报、船只升级；都不属于首个试玩范围。

## 2. 沉船打捞与拖航（推荐第二候选）

一句话：用扫描找到海底目标，定位、挂钩、拖回港口。
核心循环：扫描定位 -> 驶近目标 -> 低速挂接 -> 控制张力拖航 -> 安全交付。
有趣之处：货物惯性让过弯成为技术题，风险来自操作而不是单纯倒计时。
VR 亮点：在驾驶台切换扫描、操纵绞盘、观察拖带物；PC 对应按钮和鼠标操作。
最小试玩：一个浮在水面的打捞箱，单条约束连接与可视绳，先不做水下游泳、绳索缠绕和完整声学仿真。
工程风险：拖带刚体和浮力耦合，需要专门调参；与“危险货运”不要同时作为第一目标。

## 3. 潮汐机关：水上物理解谜

一句话：小艇不是赛车，而是启动浮台、拖动浮标、打开水门的工具。
核心循环：观察障碍 -> 选择工具/路径 -> 推拉或触发机关 -> 打开下一水域。
最小试玩：三处浮标开关与一道水门、一条可移动浮桥；海面高度固定，所谓“潮汐”先作为分段机关状态。
VR 亮点：从驾驶位观察空间关系、用探照灯找线索；电脑可完整解谜。
风险：不能把改变水位当成修改单个 Shader 参数；原版尾流、深度贴图和浮力都有水位假设。

## 4. 航线竞速 + 风险选择

一句话：保留原版竞速，但每圈能选择更危险的近道，并用有限的加速资源赌一次超越。
最小试玩：一条主航线、一条近道、计时排名和失误惩罚。
优点：距离原版最近，最快验证“好不好玩”；缺点：更像赛艇扩展，独立作品辨识度弱一些。
不承诺现成联网；原版多人枚举不是可运行的多人实现。

## 5. 舰队指挥与亲自接管（后期）

一句话：在海图上安排几艘无人艇，再亲自接管关键船只完成精细操作。
核心循环：分派航点 -> 观察拥堵/危险 -> 接管干预 -> 完成多个目标。
首版用规则 AI 和航点，不依赖强化学习；格物项目只参考训练与控制接口，机器人策略不能直接控制船。
风险：多船性能、AI 绕障、接管状态和 UI 复杂，暂不适合第一版。

## 推荐的玩法验证顺序

先用“危险货运”和“打捞拖航”各做一个很小的灰盒试玩，用户试玩之后再确定题材与美术。
需要验证：是否愿意重复第二次、是否自然产生路线决策、失败是否易于理解、VR 是否舒适。
首个正式版本只保留一个核心循环，不同时堆救援、科研、巡逻、经营、联机和强化学习。

## 共用的桌面 / VR 原则

任务、船只、评分只维护一套；改变的是输入、镜头、交互呈现。
电脑必须支持完整流程，而不是只能绕场景看看；VR 模拟器也不能代替普通电脑模式。
模拟器只能检查头手交互逻辑，不证明真机立体水面、帧率、散热或舒适性。
