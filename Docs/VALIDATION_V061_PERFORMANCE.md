# 0.61：保留内容的运行性能优化

日期：2026-11-03。基于当前 0.60 开发线（`56e6177b`），开发分支为 `feature/runtime-performance-v061-20261103`。本轮重点减少运行时重复分配和界面重建，兼顾电脑与 PICO。

## 会不会少东西

本轮没有删除场景、模型、道具、音效、动画或玩法，没有调整 PICO 既有的渲染比例、阴影距离、草木密度和特效预算，也没有修改存档格式。按用户选择，电脑端保留当前高帧率和垂直同步行为。原有工作区中的素材与编辑器修改继续保留。

代价是保存少量固定缓存，并在加载角色时整理两份 VR 网格。运行时的临时分配减少，VR 网格缓冲反而缩小；不增加玩家需要操作的设置。

## 改动

- **角色动画**：在角色建立时缓存动画状态和名称，运行时继续使用原动作、时间推进和混合公式。避免每帧遍历 Unity 动画组件、重复取得状态包装和名称。
- **动物状态**：高频可用性判断直接查询内部记录，避免创建查询闭包和不需要的记录副本。公开的猎物读取接口继续返回副本；捕获、死亡、未领取猎物及复活倒计时规则保留。
- **码头面板**：先组合完整的状态文字，再一次赋给界面；鱼获标题也避免中间文字赋值。同一帧复用一份待处理鱼获快照，公开读取接口继续返回副本。面板布局只在普通/鱼获模式切换时重设，避免每帧重新设置九个按钮的布局与 PhysX 碰撞框。
- **手册地图**：关闭手册或显示其他页面时，停止刷新不可见地图的材质；重新打开可见地图立即应用当前配色。
- **PICO 第一人称网格**：只压紧两份 VR 显示网格里未被任何绘制索引使用的顶点。完整角色源模型、桌面网格、手部标定和全部可见三角面保留。普通 VR 网格为 9,555 → 5,855 个顶点（减少 38.72%）；手作视图为 9,555 → 5,367（减少 43.83%）。优化前后按绘制索引展开的全部顶点数据流、子网格顺序及绑定姿态 SHA-256 一致，参考值见 [网格校验记录](Validation/V061/xr-mesh-reference.json)。这表示网格数据精简，不等于整机帧率提升相同比例。
- **PICO 测试口径**：修复电脑画质设置覆盖 PICO 预览既有 LOD 预算的问题。真实 PICO 原有 LOD 预算没有下调，仍保留全分辨率和 4x MSAA。修复前后的预览绘制量不能当作同画质的真机前后收益。
- **固定数据**：电脑端画质判断复用启动参数；店员每帧复用已有动作名称，保留全部动作。
- **发布版本**：游戏与安装包版本为 0.61.0，Android versionCode 为 61。PICO 包名保持 `com.ruanyueheng.tidefin.vr`。

优化思路参考 [Unity 垃圾回收最佳实践](https://docs.unity.cn/Manual/performance-garbage-collection-best-practices.html)；收益以下面的实际测量为准。

## 性能对比

先用同一台电脑、1080p、同一条含 18 阶段的路线，对交付过的 0.60 与 0.61 第一阶段代码优化包进行比较。此时两边预览使用相同设置，尚未加入后续 VR 网格压紧与预览口径修复。

| 同设置对比 | 0.60 测量帧数 / GC 次数 | 0.61 第一阶段帧数 / GC 次数 | 每千帧 GC 次数 | 降幅 |
|---|---:|---:|---:|---:|
| 电脑高刷新率 | 41,749 / 113 | 34,899 / 35 | 2.707 → 1.003 | 62.95% |
| PICO 画质桌面预览 | 52,603 / 146 | 41,025 / 22 | 2.776 → 0.536 | 80.68% |

这里统计 `GC.CollectionCount(0)` 的差值；Unity 的三个代际计数在这些运行中相同，不能把它们相加算成三倍回收。独立 .NET 的 0 字节规则测试与这些播放器计数是两种不同证据。

**不把减少 GC 等同于整体帧率改善。** 电脑端整条路线的 P95 为 12.47 → 12.74 ms、P99 为 17.32 → 36.96 ms；旧 PICO 桌面预览的 P95 为 8.48 → 12.41 ms、P99 为 16.72 → 28.51 ms，没有稳定下降。跟进读取到本机 RTX 5090 Laptop GPU 为 90–91°C，频率一度降至 180 MHz，驱动明确报告 `SW Thermal Slowdown: Active`。240Hz 屏幕及 vSync=1 使既有 60 帧目标被垂直同步覆盖；用户选择保留高帧率，本轮没有改限帧、散热、电源或驱动设置。因此这些慢帧也受温度降频影响，不能宣称已消除所有卡顿。

最终 0.61 发布包已通过全部 18 阶段验收：38,781 个实测帧、23 次 GC、P50 / P95 / P99 为 4.25 / 12.47 / 34.10 ms；大于 50 ms 的帧为 3 个，其中大于 100 ms 为 1 个。启动至场景就绪 5.68 秒。此轮采用修正后的既有 PICO LOD 预算，不能把其绘制量变化算作真实 PICO 降画质带来的收益，也不能与前两轮直接比较画质负载。

最终预览的港口、家园海岸、岛0、岛1白天阶段 draw_calls 中位数仍为 904 / 930 / 1,173 / 1,072，包含完整渲染流程。场景绘制仍重，未宣称已达到 PICO 真机帧预算；下一轮应在头显上用 Profiler 核对主要耗时。

完整阶段统计与原始日志位置见 [性能数据](Validation/V061/performance-summary.json)，构建与检查来源见 [验证汇总](Validation/V061/verification.json)。所有采样使用独立游戏进程，采样期间没有并行编译或打包。

## 验证边界

当前未连接实体 PICO。桌面采用 PICO 画质设置的测试只能证明相应运行逻辑与桌面渲染的变化，不能代替头显的双眼渲染、Vulkan 驱动、温度变化及长期佩戴体验。没有宣称真机帧率已达标或所有卡顿已消失。

首轮 0.60 电脑对比虽然完成全部阶段，但严格分析发现少数船只位置跳变，因此该轮不用于前后收益结论；原始记录保留，复测在不放宽验收条件的情况下通过。本轮没有把该偶发现象判定为已修复。

所有自动化使用独立存档；没有打开玩家普通存档。无需删除旧版或旧存档即可保留回退选择。
