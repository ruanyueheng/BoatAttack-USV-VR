# How to Fish（渔力全开）玩法调研与 BoatAttack 适配提案

调研日期：2026-09-24。状态：仅调研/设计，不代表批准实施；本轮没有修改运行时代码、场景或包依赖。

## 1. 对象与证据边界

对象是 Dazed Games 的 How to Fish，Steam App ID 4001890，中文商店名《渔力全开》。官方商店列出的发行日是 2026-08-20。[S1]

本次读取官方商店、开发商网站、更新公告，观察商店内演示画面，并抽样阅读玩家评价；没有购买、安装或亲自完整游玩，也没有获取该游戏源代码。部分商店动图标有 Demo 0.0.5，不能把其中的按键/UI 当成现版本规格。

多人信息有版本差异：商店首段仍写 1–4 人，1.0.4 公告明确新增最多 8 人房间。不要只依据宣传首段认定当前上限。[S1/S3] 没有在所查官方资料中确认原生 VR 支持；普通手柄或 Steam Deck 支持不是 PICO 独立运行证明。

## 2. 它的核心不是“写实垂钓”

官方描述确认的组合是：物理交互式捕鱼，鱼的处理与出售，装备/武器成长，任务和首领推动岛屿进展，以及稀有鱼变体、花式射击收益和游戏内赌博。[S1]

我的设计解读（不是开发者原话）：

- 操作层：物品与鱼是能拿取、丢弃、抛出的对象，短时动作反馈比长时间等鱼重要。
- 收益层：捕获和处理产生收入，技术表现与稀有物种提供额外目标。
- 进展层：新装备和岛屿让玩家面对不同威胁，而不只增加一个价格数字。
- 社交层：同伴和物理意外制造即兴场面。不能假设移除联网后，同样规则仍然足够有趣。

官方演示可见第一人称手部/工具、钓竿及夸张鱼类动作；它与严肃钓鱼训练或纯休闲垂钓不是同一种方向。我们应借鉴交互规则，不复制角色、岛屿布局、界面、美术、声音或游戏文件。

## 3. 值得借鉴的六项，及我们的改法

### A. 有实体反馈的捕获物：优先

参考点：鱼不是进背包后消失的图标。

我们的改法：鱼到船边后，需要抄取/抓住、放入鱼箱；它可以扑腾、滑落，制造小意外。不要让贵重鱼或工具被数值异常弹飞后永久丢失。先让少量近处对象参与刚体模拟，箱内用库存数据保存，外观只是表现。

### B. 一条短而完整的赚钱循环：优先

参考点：获得资源能立刻改善下一轮体验。

我们的改法：开船找鱼区 -> 停船捕捞 -> 收箱 -> 回港出售 -> 购买一次功能升级 -> 再出港。升级优先改变处理方式，例如更易控的鱼线、更大的抄网或更安全的鱼箱，而不是只提高售价。首版不加入燃料、饥饿、维修、烹饪等多套消耗。

### C. 鱼的行为差异，而不是仅换贴图：优先

参考点：不同生物构成不同挑战，官方补丁也多次调整鱼类强度。[S4/S6]

我们的改法（原创提案，不是已确认的原作鱼种规则）：普通鱼容易上手；冲刺鱼需要松紧交替；挣扎鱼到船边后仍需要主动收捕。再用一个稀有外观变体提供收集目标，不需要先做十几种模型或复杂水下 AI。

### D. 技巧带来额外收益：小规模尝试

参考点：原作明确给花式射击额外金钱。[S1]

我们的改法：精准抄取、无失误收捕、及时收箱可获得清楚、可解释的小额奖励。不要把 PC 的快速转视角/甩枪直接移植成 VR 的甩头或连续大幅挥臂，也不要让技巧加分成为新手赚钱的必需条件。

### E. 渔区与装备共同推进：第二阶段

参考点：原作以任务/首领和岛屿构成进展。[S1]

我们的改法：先在原海岛周围布置几个不同渔区，而不是立即新增岛屿。渔区的鱼、障碍和靠近方式不同，让开船有意义。首版使用一张订单或图鉴目标，不做多个 NPC、剧情任务链与首领战。

### F. 分工合作：后期，不是第一步

参考点：驾驶/寻找目标/捕捞/收纳很适合自然分工。

我们的改法：先保证单人能完成全部流程，再考虑朋友分别驾驶和捕捞。BoatAttack 中的 Multiplayer 枚举不是现成联网功能；移动船只上的玩家、鱼、工具和所有权同步需要独立设计。PICO/PC 跨平台联机也不是已经具备的能力。

## 4. 推荐先验证的方向：《怪鱼航线》（工作名）

定位：轻量、夸张的船上物理捕捞，不是硬核钓鱼模拟，也不直接变成大规模枪战。

一轮目标体验：从渔港出发，自己选择渔区；停船后用工具把一条有反应的鱼带到船边；主动收捕并装箱；带回港口换取一次明确的改善，再选择是否挑战更难的渔区。

第一版拟定范围（只是设计约束，不是已经实现的功能）：

- 复用一个海岛；一个交付点、三个渔区。
- 一艘玩家船、一个固定船侧操作站；先不做船上自由行走或上岸探索。
- 一根竿与一个收捕工具；鱼线先做简化松紧规则和视觉线，不做完整绳索/柔体仿真。
- 三种行为差异、一种稀有外观；不上大型首领或成套枪械改装。
- 一种鱼箱、一处出售交互、一项功能升级；首先保证单人循环。
- 先做桌面完整流程，再接真实 VR 操作；任务/鱼/经济共用一套逻辑。

关键：如果只做“按 E 等待、鱼进背包”，就没有借到这款游戏最值得参考的实体交互；如果第一版就加枪械、赌博、多岛、多人与海怪，又会稀释 BoatAttack 的驾驶优势并扩大范围。

## 5. 与当前 BoatAttack 工程的真实对应关系

已检查的现有能力：Unity 2022.3.62f1 / URP 14、水面与浮力、海岛、Boat/Engine 驾驶、PC/XR 输入路由，以及上轮通过的单人竞速流程。已有 FisherBay 建筑组合 prefab，可作为渔港视觉素材候选；没有据此假设它已经有商店功能。

需要新建或解耦的部分：

1. **模式边界。** RaceManager 的流程绑定航点、竞速 UI、倒计时和四艇生成；Boat.Update/FixedUpdate 也依赖 RaceStarted 与航点。捕鱼不能简单通过改圈数、强行设置 RaceStarted 或关闭 AI 来伪装。应保留原竞速回归，单独建立捕鱼模式入口并隔离竞速进度逻辑。
2. **输入上下文。** USVInputState 当前的 interact 是一次按下命令，没有持续收线、抓取/松手等完整状态。未来需要明确 Driving 与 Fishing 的输入消费权，防止一次扳机操作同时开船和抓鱼。PC 按键与 XR 动作只映射到同一捕捞命令，不维护两套玩法。
3. **停船而非暂停世界。** 捕鱼时抑制推进并提供可控停靠，不用 Time.timeScale=0 冻结全世界，也不能随意关掉浮力。船、鱼与水的逻辑必须继续运行。
4. **相机。** Boat.LateUpdate 仍有随速度变化的 FOV，这是桌面竞速相机逻辑，不能直接用于头显。VR 应保留真实头部跟踪、稳定参照和舒适的固定操作站位；loader、rig 和真机渲染本身尚未验收。
5. **鱼类与资源。** 新增鱼行为、工具、鱼箱、订单/出售、图鉴或存档；现有水面不是现成鱼类生态系统。远景鱼群不必是刚体，近处捕获物才参与必要模拟。
6. **物理持有。** 被握住的工具与鱼应避免和玩家/船体形成互相推挤的高能量碰撞；释放后再进入受控物理状态。设置掉落找回、速度约束及合理回收，而不是让重要物品静默消失。
7. **现有风险。** PROJECT_HEALTH_CHECK.md 已记录水面采样 Registry 缺少注销、清理后静态状态不完整，以及场景加载失败缺少恢复。大量鱼对象创建/销毁前，应先完成相关生命周期测试与修复。

建议的代码责任划分（仅提案，不创建这些脚本）：

- FishingMode：模式、站位和驾驶/捕捞切换。
- CatchSession：纯逻辑状态与成功/挣脱判定。
- FishDefinition：物种、行为参数、外观、基础价值等配置。
- FishActor/ToolInteractor：场景表现、有限物理、抓取与工具。
- CatchInventory/TradeService：以稳定 ID 记录捕获物，防重复入箱或重复出售。
- SaveService：保存数据、版本、备份与恢复，不靠场景里剩下几个刚体推断进度。

这些边界有利于朋友分工，但第一版也可以合并较小模块；不应为了架构先堆大量空类。

## 6. 从补丁和评价学到的“不要照搬”

官方 1.0.10 增加了地面物品跨会话保存（上限 64，按物品类别优先），并限制爆炸造成的物品速度；1.0.11 增加坏存档检查与备份；1.0.12 又限制了物品速度以减少丢失。[S4/S5/S6]

这提示我们的首版应把以下项目当作基本体验，而不是后期优化：

- 已入箱鱼、货币与升级明确保存，物理展示与进度数据分开。
- 交易原子化，重复触发不会重复得钱；工具掉水有明确找回规则。
- 退出、重进、切场景后数量和余额一致；异常存档可回退备份。
- 有趣的物理失误是可理解、可恢复的，不能把数据丢失当成挑战。

评价抽样方法：Steam API 的 all 排序中读取 8 条负评和 6 条英文正评，主动寻找风险，不是随机或代表性抽样。[S7/S8] 部分样本强调同伴整活，部分提到单人难度/重复、物品或存档丢失。它们只能提供问题线索；尤其早期丢失反馈不能被描述成现版本仍未修复，因为后续公告已有对应改动。

暂不借鉴：完整枪械配件树、大型首领、复杂破坏、自由角色攀爬、赌博系统和多人互相伤害。它们不是坏设计，但与首个“船上物理捕捞”验证目标关系较弱，且会引入额外战斗、内容、联网或舒适性工作。

## 7. 首个灰盒应该回答的问题

下面是未来验收计划，不是本轮已通过的测试：

- 单人不用朋友制造笑点，是否仍想再捕一条、再去一个渔区？
- 不同鱼是否需要不同操作，而不只是更长的进度条？
- 玩家能否判断失败是收线过急、松线过久或没有及时收捕？
- 捕捞时是否完全隔离驾驶输入；失焦/失去追踪/松手后输入是否归零？
- 鱼箱、出售与重进是否可靠；操作失败能否恢复，而非永久损失关键工具？
- 原版竞速主菜单往返和既有自动检查是否仍通过？
- 实际 PICO 上的双眼水面、操作站位、物理数量、帧时与舒适性是否达标？不能用桌面截图代替。

建议先批准最小范围，再制作桌面灰盒；不要在本次调研中默认开始玩法、导入第三方资产或安装联网 SDK。
